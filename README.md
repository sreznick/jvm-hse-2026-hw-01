# Домашнее задание: «Система обработки данных автомагазина»

## Цель

Разработать консольное приложение на Kotlin, которое загружает данные о товарах автомагазина из «грязного» CSV-файла, приводит их к единому формату и сохраняет в различные форматы через расширяемую архитектуру.

---

## Исходные данные

CSV-файл содержит информацию о товарах (масла, шины, аксессуары). Данные неструктурированы и содержат проблемы:

- Опечатки в названиях колонок
- Цена указана в разных валютах (доллары и рубли)
- Вес указан в разных единицах (фунты и килограммы)
- Пустые поля и некорректные значения
- Запятые внутри названий товаров (в кавычках)
- Разные товары имеют разные характеристики (вязкость, диаметр, материал)

---

## Формат входного файла

### Общие правила

- Файл: input.csv
- Кодировка: UTF-8
- Разделитель полей: запятая
- Первая строка — заголовок с именами колонок
- Поля, содержащие запятые, заключаются в двойные кавычки
- Двойные кавычки внутри поля экранируются удвоением
- Пустые поля допустимы
- Порядок колонок фиксирован

### Структура строки

id,name,type,price,weight,vehicle,extra

### Описание колонок

| Колонка | Тип | Обязательность | Описание |
|---------|-----|----------------|----------|
| id | Целое число | Обязательно | Уникальный идентификатор товара |
| name | Строка | Обязательно | Название товара. Может содержать запятые (в кавычках) |
| type | Строка | Обязательно | Тип товара: oil, tire, accessory |
| price | Число с валютой | Обязательно | Цена. Формат: число и валюта ($ или руб). Число может быть целым или дробным (разделитель — точка) |
| weight | Число с единицей | Обязательно | Вес. Формат: число и единица (kg или lb). Число может быть целым или дробным (разделитель — точка) |
| vehicle | Строка | Обязательно | Тип автомобиля: PASSENGER, TRUCK, MOTORCYCLE |
| extra | Строка | Опционально | Дополнительные характеристики. Формат: ключ=значение;ключ=значение |

### Формат поля extra

Поле extra содержит одну или несколько пар ключ=значение, разделенных точкой с запятой.

Допустимые ключи зависят от типа товара:

| Тип товара | Допустимые ключи |
|------------|------------------|
| oil | viscosity (строка, например 5W-30), volume (число, литры) |
| tire | diameter (число, дюймы), season (строка: SUMMER, WINTER, ALL_SEASON) |
| accessory | material (строка), color (строка) |

Неизвестные ключи игнорируются.

## Требования к функциональности

### Загрузка и обработка данных

Приложение должно:

1. Читать CSV-файл с товарами
2. Корректно разбирать строки с учетом кавычек и запятых внутри полей
3. Приводить все цены к рублям, весь вес — к килограммам
4. Определять тип товара (масло, шина, аксессуар) и сохранять соответствующие характеристики
5. Проверять корректность данных:
   - Цена и вес должны быть положительными
   - Название не должно быть пустым
   - Объем масла должен быть числом
   - Цвет аксессуара должен быть из допустимого списка (черный, белый, серебристый)
6. Пропускать некорректные строки, собирая список ошибок с указанием номера строки и причины

### Сохранение результатов

Приложение должно поддерживать сохранение обработанных данных в разные форматы:

- JSON
- XML
- Текстовый отчет

Архитектура должна позволять добавлять новые форматы без изменения существующего кода обработки данных.

Пользователь выбирает формат сохранения в начале работы (или через аргумент командной строки).

### Отчетность

После обработки приложение выводит статистику:

- Сколько строк обработано
- Сколько товаров успешно загружено
- Сколько ошибок парсинга
- Сколько ошибок валидации

Список ошибок выводится в консоль с деталями.

---

## Требования к обработке ошибок

При обнаружении ошибки приложение должно:

1. Пропустить некорректную строку
2. Записать ошибку в отчет с указанием:
   - Номера строки (нумерация с 1, строка заголовка не учитывается)
   - Причины ошибки (человекочитаемое описание)
3. Продолжить обработку следующих строк

---

## Требования к качеству кода

- Код должен быть разделен на логические модули (загрузка, обработка, валидация, сохранение)
- Обработка ошибок должна быть единообразной
- Код должен быть покрыт юнит-тестами для ключевых сценариев:
  - Разбор строк с кавычками и без
  - Конвертация валют и веса
  - Валидация корректных и некорректных данных
  - Работа реестра форматов сохранения
  - Корректность генерации каждого формата
